# Phase 1 Plan 01 — Workspace 管理与持久化

## Objective

实现 v1.0 的 Workspace 配置闭环：后端模型/存储/校验/端口分配 + Wails 绑定接口 + 第一版中文管理 UI。

## Preconditions

- 以 `.planning/PROJECT.md` 和本目录 `01-CONTEXT.md` 为约束来源。
- 不读取或复制 `codexprov3` 源码。
- 不实现进程启动/停止、PID、托盘、自启执行；这些属于后续 Phase。
- 当前 MCP bash 环境没有 `go`，所以代码阶段可以完成静态实现与 diff 审核，但最终 `go test` / `wails build` 需要在具备 Go/Wails 的执行环境补跑。

## Task 1 — 建立配置领域模型和 Store

**Files:**
- 新建 `config.go`
- 新建 `config_test.go`

**Implementation:**
1. 定义 `Config`、`PortRange`、`Workspace`、`WorkspaceInput`。
2. 实现默认配置：Version=1，PortRange=8800-8899，Workspaces=[]。
3. 实现配置路径解析：`~/.config/codexpro-plus/config.json`；产品改名后兼容迁移旧 `~/.config/codexprov4/config.json`。
4. 实现 `ConfigStore`：
   - Load
   - Save（同目录临时文件 + rename）
   - 首次缺失时返回默认配置
   - JSON 损坏时明确报错，不覆盖原文件
5. 确保持久化模型不包含任何未来 `Instance` 运行时字段。

**Tests:**
- 默认配置
- round trip
- 中文 alias/path
- malformed JSON

## Task 2 — Workspace 校验与端口分配

**Files:**
- 新建 `workspace_service.go`
- 新建 `workspace_service_test.go`

**Implementation:**
1. 建立 `WorkspaceService`，持有 `ConfigStore` 和可替换的端口可用性检查函数，便于测试。
2. 实现：
   - List/GetConfig
   - AddWorkspace
   - UpdateWorkspace
   - DeleteWorkspace
   - UpdatePortRange
3. Workspace ID 使用稳定随机 ID，不以数组下标、Alias、Path 作为主键。
4. Windows 路径比较采用规范化 + 大小写不敏感语义，防止重复目录。
5. 自动端口：从范围起点向上扫描，跳过配置占用和系统占用。
6. 手动端口：验证合法值、Workspace 间冲突、系统占用。
7. 编辑时排除当前 Workspace 自身端口，允许原值保持不变。
8. 端口范围变更只影响未来自动分配，不静默改写已有 Workspace 端口。

**Tests:**
- 空 alias / 非绝对路径 / 不存在目录
- duplicate path
- invalid/duplicate manual port
- auto port skip configured/busy
- range exhausted
- edit keeps own port
- invalid port range
