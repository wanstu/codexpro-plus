# Phase 4 Plan 04-01 — 复制反馈与 Workspace 访问地址

## 目标

完成 v1.0 发布前第一批 UX 改进，并保持“复制域名”和 CodexPro 实际监听配置严格解耦。

## Tasks

1. 配置模型
   - `Config` 增加 manager-level `domain`。
   - schema 升级并兼容 v1/v2/v3 配置。
   - 增加保存 domain 的 service/app API。

2. URL 生成
   - 增加统一 `buildWorkspaceURL(workspace, config)`。
   - 空 domain 默认 `127.0.0.1`。
   - 无 scheme 默认 `http://`；保留显式 `http://` / `https://`。
   - 拒绝带 path/query/fragment 或自带端口的 domain，避免与 Workspace port 冲突。
   - 最终 URL 固定为 `<scheme>://<domain>:<port>/mcp`，并附带当前 Workspace Token 查询参数。
   - 提供获取完整 MCP URL 与用系统默认浏览器打开 URL 的 App API。

3. 前端 UX
   - 管理器设置新增“复制链接域名”输入与保存按钮。
   - 明确说明该设置不会改变 `CODEXPRO_HOST` / 实际监听。
   - Workspace 卡片显示掩码后的完整 MCP 链接，Token 不直接明文铺在卡片上。
   - 增加“打开”和“复制链接”按钮；不提供单独“复制端口”。
   - 所有复制统一走 helper，成功统一提示“复制成功”，失败显示原因。
   - 启动/停止/保存等普通操作反馈使用短时 Toast；顶部 message 区仅保留需要持续展示的错误、警告或公告。
   - 应用标题栏 / 任务栏构建图标和托盘图标统一使用 CodexPro+ 应用图标，不再使用 Wails 默认 W。

4. 测试
   - 配置 round-trip / migration 覆盖 domain。
   - service domain validation/persistence 测试。
   - URL formatter 表驱动测试。
   - 确认 ProcessManager 中 `CODEXPRO_HOST` 仍固定为 `127.0.0.1`。

5. Release review
   - `gofmt`。
   - `go test ./...`。
   - Wails production build 延后到不影响当前运行实例时执行；只 build 验证，不启动产物。
   - review diff，确认无 domain -> process 环境串线。
   - 更新 `.planning/STATE.md`。
