# Phase 2 Plan 01 — codexpro 进程生命周期

## Objective

实现手动启动/停止、运行实例、状态轮询和日志闭环。

## Tasks

### Task 1 — 配置迁移与 CodexPro 参数
- 配置版本升级到 v3。
- Workspace 增加稳定 `token` 以及 `bash_mode` / `write_mode` / `tool_mode` / `inherit_env`。
- 新 Workspace 默认生成 32 字节 token，也允许用户指定至少 24 字节的 token。
- v1/v2 配置 Load 时自动补齐参数并迁移；默认保持 `full / workspace / full / inherit-env=true`。
- Update Workspace 留空 token 时保留原 token；显式填写时校验后更新。

### Task 2 — ProcessManager
- 新建 `process_manager.go`。
- 解析同目录 `codexpro-core.exe`。
- 启动时设置 Workspace root / port / token，并从 Workspace 读取 bash/write/tool/inherit-env。
- 维护 runtime-only Instance map 和 starting 状态；同一 Workspace 启动中/运行中不得重复拉起。
- 捕获 stdout/stderr 到独立日志。
- Wait goroutine 处理异常退出并记录 last error。
- 停止时终止完整 Windows 进程树。
- 显式退出时 StopAll。

### Task 3 — Wails bindings
- `StartWorkspace(id)`
- `StopWorkspace(id)`
- `GetRuntimeStates()`
- `GetWorkspaceLog(id)`
- 正在运行时拒绝编辑/删除。

### Task 4 — UI
- Workspace 卡片加入运行状态、PID、启动/停止、日志。
- 启动请求发出后立即进入本地 pending 状态并禁用按钮；后端 `starting` 状态同步后继续锁定，避免重复点击。
- Workspace 编辑弹窗增加 Token / Bash / Write / Tool / Inherit Env 配置。
- 新增运行实例区域，可点击定位卡片。
- 1.5 秒轮询 runtime state。
- 自动退出/启动失败显示明确错误。

### Task 5 — Verification
- `go test ./...`
- `wails build`
- 人工验证两个 Workspace 同时运行、单独停止、异常退出、日志。
